# STAV DETAIL — первый продаваемый демо-проект

Это не настоящий бизнес, а готовый шаблон для портфолио и демонстрации клиентам. Название, телефон, адрес, цены и статистика вымышлены — перед публикацией для реального клиента их необходимо заменить.

## Второй пример портфолио

В папке `portfolio/pauza-coffee` находится отдельный адаптивный демо-лендинг городской кофейни «ПАУЗА». Его можно открыть напрямую через `portfolio/pauza-coffee/index.html`. Это вымышленный концепт: адрес, контакты, меню и цены не относятся к реальному бизнесу.

## Что уже сделано

- адаптивный одностраничный сайт;
- форма с браузерной и серверной валидацией;
- безопасная отправка заявок в Telegram через сервер;
- honeypot и простое ограничение частоты запросов;
- демо-режим без токена Telegram;
- отсутствие платных npm-зависимостей;
- базовые защитные HTTP-заголовки.

## Как запустить

Нужен Node.js 18 или новее.

Файл `public/index.html` можно открыть напрямую для быстрого просмотра дизайна. Форма заявки при таком открытии работать не будет: браузеру нужен запущенный сервер, который безопасно хранит Telegram-токен.

```powershell
cd C:\путь\к\vibe-starter-demo
npm start
```

Откройте `http://127.0.0.1:3000`.

Без настройки Telegram форма работает в демо-режиме: заявка выводится в терминал, где запущен сервер.

## Публикация на Render

В корне проекта находится `render.yaml`. Он описывает бесплатный Node.js Web Service:

- регион Frankfurt;
- сборка `npm install`;
- запуск `npm start`;
- автоматический деплой после каждого push в GitHub;
- проверка работоспособности по пути `/`.

При создании Blueprint в Render выберите этот GitHub-репозиторий. Сайт запустится в демо-режиме. Для реальных Telegram-заявок добавьте в настройках сервиса секретные переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

## Как подключить Telegram

1. Создать бота через официального `@BotFather` и получить токен.
2. Написать новому боту любое сообщение.
3. Получить `chat_id` через метод `getUpdates` Telegram Bot API.
4. Создать переменные окружения перед запуском:

```powershell
$env:TELEGRAM_BOT_TOKEN="токен_бота"
$env:TELEGRAM_CHAT_ID="идентификатор_чата"
npm start
```

Никогда не добавляйте настоящий токен в `public/script.js`, GitHub, скриншоты или переписку с ИИ. На сервере хостинга значения задаются через раздел переменных окружения.

## Что менять для клиента

Ищите вымышленные данные в `public/index.html`:

- STAV DETAIL;
- демонстрационный телефон;
- адрес;
- цены;
- услуги;
- цифры 5 лет / 420+ / 4,9;
- тексты и заголовки.

Цвета меняются в начале `public/styles.css` через переменные `--asphalt`, `--gunmetal`, `--ceramic`, `--signal` и `--glass`.

## Честные ограничения

Для реального запуска дополнительно нужны:

- домен и HTTPS;
- политика обработки персональных данных с реквизитами владельца;
- резервный канал связи;
- постоянное хранилище или CRM, если нельзя терять заявки;
- журналирование без записи лишних персональных данных;
- внешний rate limit для нескольких серверов или серьёзного трафика;
- реальные фото, на использование которых у клиента есть права.

Этот шаблон нельзя обещать как интернет-магазин, CRM или защищённый личный кабинет.

## Как превратить проект в кейс

1. Перепишите тексты своими словами.
2. Измените одну секцию без помощи ИИ.
3. Добавьте реальные фотографии только с разрешения владельца.
4. Запишите видео на 45–60 секунд: мобильная версия → услуги → отправка заявки.
5. Опубликуйте код на GitHub без `.env`.
6. В описании честно укажите: «демо-концепт для локального детейлинга».
